# ivitals 代码审计报告

- 日期：2026-11-21
- 范围：`src/`（4121 行）与嵌入的 `src/collector/scripts/collect.sh`
- 方式：只读静态审计。未修改、重启或干扰正在运行的 `ivitals`，未改动 `data/`。
- 结论：核心链路（采集 → 错误传播 → 单写线程落盘）整体设计正确；主要风险集中在
  **一个 UTF-8 切片 panic**、**慢主机导致的整轮阻塞**、**flush 错误处理** 和
  **extras 的静默缺失**。

## 一、重点问题结论

| 检查项 | 结论 |
|---|---|
| 无 GPU 机器的 NVML 降级 | **通过**。初始化失败 / 0 设备 → `absent`，运行时失败 → `error`；状态缓存，每种状态只 warn 一次，不会每轮刷日志（`src/collector/nvml.rs:96-111,140-145`）。远端脚本同理：无 `nvidia-smi` → `absent`，有但失败 → `error`。 |
| `spawn_blocking` 错误捕获 | **基本通过**。`JoinHandle::await` 的 `Err`（panic）与采集 `Err` 都被处理；采集错误每 alias 每 60s 记一次 warn 并跳过该 tick，不会写伪值（`src/scheduler.rs:148-196`）。但 extras 解析失败、跨天 flush 失败、writer 线程死亡仍可能静默丢数据（见下表）。 |
| 是否会误删当天文件 | **不会**。`cutoff = today - retention_days`，仅删除 `date < cutoff` 的目录；当天与边界日都保留（`src/storage.rs:71,83`）。注意：按目录整删，理论上前进时钟/乱序记录可能让已打开的文件被 unlink。 |
| BufWriter 跨天 flush | **会 flush，但不健壮**。跨天通过 `self.files.remove(&key)` 触发 `BufWriter::drop`，而 `Drop` 会忽略 flush 错误；`flush_all` 的失败也只打日志、不进入失败计数（`src/storage.rs:149-163,184-192`）。 |
| `MissedTickBehavior::Skip` | **已设置**（`src/scheduler.rs:103`）。但它只防止 tick 积压；由于每轮 `collect_round` 串行等待所有任务，慢 SSH 会拖慢所有服务器的采样节奏。 |
| 不必要的 `unwrap()` | **没有会直接杀死主进程的输入路径 unwrap**；生产代码中的 `unwrap/expect` 都是不变量或启动期断言。真正的输入相关风险是 `truncate()` 的 UTF-8 字节切片 panic（见 #1），以及 `disk_io` 中一个当前不可失败、但未来可能失败的 `unwrap`。 |

## 二、问题清单

### 新增记录能力

- GPU：每卡 util、显存、温度、功耗/上限、风扇、SM/MEM 时钟、P-state；本地 NVML 同时输出 `gpu_detail`。
- 多核：每 tick 记录 `per_core_percent`（2 位小数）、min/mean/p50/max/p95、>50/>90 核数、10 桶直方图。
- 文件系统：每挂载点 total/used/available/inodes；伪文件系统过滤。
- 网络：聚合 + 每接口 bytes/packets/errors/drops 每秒速率。
- 进程：Top N 提升到 50，新增 RSS、线程数、启动时间、状态计数、总线程数、GPU compute/graphics 进程；每行还记录用户/UID/GID、父进程、完整命令行、cwd、exe（有长度上限）。
- 内存：buffers/slab/dirty/writeback、swap 总量与速率。
- 主机身份：每次启动/每天一条 `*-host.jsonl`，记录 hostname、OS、内核、架构、CPU 型号、核数、内存总量、启动时间与 GPU 型号。

## 四、修复优先级

1. **立即（P0）**：#1 UTF-8 panic、#4 慢主机队头阻塞、#6 Slurm 无超时。三者都可能让采集在某台机器上停摆或整体变慢，且修复面小。
2. **本轮迭代（P1）**：#2/#3 落盘 flush 错误、#7/#8 远端进程数据质量、#5 extras 静默缺失、#9 writer 健康检查。
3. **后续（P2）**：#10 NVML 错误恢复、#11 远端时间戳、#12 DNS 超时、#13/#14 unwrap 整理、#15 retention 边界、#16 告警 key。

## 五、已确认的良好设计

- 无 GPU 是一等公民：`GpuStatus` 三态 `absent/ok/error`，本地 NVML 失败缓存、只 warn 一次；远端无 `nvidia-smi` 也是 `absent`。
- 采集失败不写伪值：`CollectError` 向上传播，调度器跳过该 tick，warn 限流 60s。
- 单写线程 + 按记录 `ts_ms` 的 UTC 日期分区，避免多线程写同一文件；跨天会重新打开文件。
- retention 只识别严格 `YYYY-MM-DD` 且真实存在的日期目录，非日期目录与散落文件不碰。
- `MissedTickBehavior::Skip` 已用于避免长停顿后的补跑风暴。
